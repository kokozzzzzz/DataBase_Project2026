| 正式到站开单 | 接 A 的 RESERVATION / QUEUE 资格，要求 CHECKED_IN 和本车未释放占位。现场车主先走 A 的 WALK_IN 排队、叫号及核验。SQL 的 DIRECT 枚举保留供历史兼容，当前正式服务拒绝无资格直充 |

| 启动余额 | 使用 D 的真实用户、车辆、有效状态和实名结果。B 服务默认预检 5.00 元，可由受信任调用方传 minimum_balance 配置。该值为当前 B 配置，老师只要求校验余额 |
| 事务 | 服务接收公共 connection，不自行提交。调用方用 transaction(connection) 包含整个业务操作，异常应传播到事务外以完整回滚 |
| 枪位 | 沿用同站一枪一位；当前占位读取 A 的 parking_occupancy。充电结束不释放车位，驶离调用 A 的 release_parking_space |
| 计费 | 北京时间、秒精度的无时区 DATETIME；费率区间左闭右开。可信累计读数必须包含起点、终点和每个电价边界；服务计量单位先 ROUND_HALF_UP 到 6 位，与保存快照一致，再按每个连续费率段分别将电费、服务费 ROUND_HALF_UP 到分后求和 |
| 免费与起步 | 开单所用版本决定免费服务分钟与优惠前最低费用；免费项只免服务费。服务费按 KWH 或 MINUTE。跨日按每段实际有效版本取电价与服务单价 |
| 异常 | 缺边界、费率断档/重叠、主动标记断连进入 REVIEW。人工复核须填依据，补录仅限本单停止时点以内的可信读数。仍缺数据时保留 REVIEW |
| 账单与券 | 已出账后先调用 D 锁券，再由 B 记录确认。任意外部优惠金额不直接传入 B 确认入口。零应付可在确认事务中核销券，无需伪造零元支付流水 |
| 分次支付 | 支付记录表示收到的外部支付结果，成功额累计不得超过应付。部分支付保留锁券，足额成功与 D 核销在同一事务完成 |
| 首笔失败 | 没有任何成功支付时，失败流水、D 释放锁券、优惠清零和确认失效同时完成。后续重试先重新确认账单。有部分成功支付后遇失败，保留优惠和锁券，等待补缴 |
| 退款 | 只登记成功的外部退款事实。锁订单后锁原成功支付，累计退款不超原支付，按 refund_ref 幂等。退款后已核销券继续保持 USED；返券需要 B/D 另定规则 |
| 支付介质 | 当前记录外部渠道凭证，不在 B 服务直接扣 D.balance。余额支付需要 D 提供账户流水、扣款及退回事务后接入；测试渠道明确为 TEST_EXTERNAL |
| 并发读 | 支付、退款和券支付判定用当前读，避免 RR 事务已有旧快照时使用过期汇总。死锁或锁超时交给调用方回滚整笔并按相同资格/流水键重试 |

## 给 A

已实测调用 check_in_reservation、consume_admission、release_parking_space，创建订单和资格消费属于一个事务。B 不重复创建 A 的表或另一份占位。

请 A 继续使用现有资格编号。B 阶段测试集的预约编号为 7200001–7200020 和 7200101–7200120；这些是固定历史导入样例，正式预约仍调用 A 的 create_reservation。后续如允许“预约结束后迟到宽限仍可开单”，需要同时调整 B 区间校验，并保留边界测试。

A 自有 9000 段共享夹具与本测试集采用不同编号。已执行 A/00_local_shared_fixtures.sql 的本机可以保留它，使用 B 固定测试集时按 7200000 段标识选择数据；全局演示最终选定同一套编号。

锁顺序方面，B 先锁资格，再锁设施、用户车辆、占位，最后插入新订单并消费资格；资金事务先锁订单，随后使用 D 券服务的订单→券顺序。A 的预约、取消及驶离过程有各自锁路径，交叉请求遇死锁需整笔回滚重试。本次验证同资格两个连接并发开单只生成一单，未宣称所有 A/B/C 并发组合均已覆盖。
