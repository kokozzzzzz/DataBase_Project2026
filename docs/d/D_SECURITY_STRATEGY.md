# D 模块登录与应用安全策略

## 1. 适用范围和实现边界

本方案覆盖 D 负责的④用户与会员运营、⑤结算与对账，以及 Python 持久层访问数据库时的安全控制。

当前课程项目没有 Web 登录接口、会话服务器和统一员工账号表，`user` 表也不保存登录密码。因此本文件区分两类内容：

- 已实现：MySQL 最小权限角色、参数化 SQL、事务边界、敏感字段密文/摘要字段、脱敏视图、配置与密码隔离；
- 上线时实施：终端用户密码认证、失败锁定、会话令牌、密钥轮换和安全审计。

不为了满足文档要求而在 D 模块擅自增加账号表。统一身份认证的表结构和负责人应由全组确认后再实施。

## 2. 身份认证策略

如果后续增加密码登录，应遵循以下规则：

1. 只保存专用密码哈希算法的结果，不保存明文密码或可逆加密密码。
2. 优先使用 Argon2id；算法参数、版本和随机盐与哈希结果一起保存，便于登录成功后逐步升级参数。
3. 每个账号使用独立的密码学安全随机盐；可额外使用存放在数据库之外的全局 pepper。
4. 密码重置必须使现有会话失效；重置令牌只能使用一次、短时有效，并仅保存令牌摘要。
5. 管理员、运营和结算账号启用多因素认证；数据库 root 账号不得用于应用连接。
6. 不在日志、异常、Git、`.env.example` 或测试夹具中记录真实密码。

## 3. 登录失败和会话控制

- 以账号和来源地址两个维度记录失败次数，避免只依赖单一 IP。
- 同一账号15分钟内连续失败5次后锁定15分钟；继续失败采用逐步延长等待时间，并保留人工解锁入口。
- 无论账号是否存在，登录失败返回相同的通用提示，降低账号枚举风险。
- 登录、失败、锁定、解锁、密码重置和角色变更均写入只追加的安全审计日志。
- 会话令牌使用密码学安全随机值；服务端仅保存令牌摘要，禁止放入 URL。
- 普通会话闲置30分钟失效、最长8小时；高风险操作要求重新认证。角色或密码变化后立即撤销旧会话。
- Web 部署时 Cookie 使用 `Secure`、`HttpOnly` 和合适的 `SameSite` 属性，并配置 CSRF 防护。

上述时间和次数是课程设计基线，正式上线时应结合学校或企业统一身份平台的策略调整。

## 4. 数据库权限控制

`sql/D/06_security_roles.sql` 已实现三类最小权限角色：

- `cp_d_reporting`：只读脱敏视图及视图必需的安全列；
- `cp_d_membership_operator`：维护 D④表并执行优惠试算过程；
- `cp_d_settlement_operator`：维护 D⑤表并执行结算生成过程。

三个角色均不拥有 `DELETE`、DDL、账号管理或转授权权限。④与⑤写权限相互隔离，实际验收 `R01～R07` 全部为 `PASS`。

应用部署时为每个服务创建独立 MySQL 账号，只绑定一个所需角色。管理员账号仅用于安装、升级、备份和恢复，不进入应用 `.env`。

## 5. SQL 注入防护

- D 的 Python 持久层和值查询统一使用 PyMySQL `%s` 参数占位符，不拼接用户输入值。
- 可选筛选条件只从代码内固定片段组合，状态值和分页范围先通过白名单或数值边界校验。
- 表名、列名和排序方向不能使用普通参数占位符；如业务确需动态标识符，只能从固定映射表选择。
- 禁止把 HTTP 参数、表单值或外部文件内容直接交给 `execute()`；禁止用字符串格式化生成数据值。
- 数据库异常对外转换为通用业务错误，详细 SQL 和连接信息只进入受控日志。
- 单元测试继续覆盖非法状态、边界值、重复写入、外键失败和事务回滚。

## 6. 敏感数据和密钥管理

- 手机号、车牌、统一社会信用代码和税号使用带认证的对称加密保存；推荐 AES-256-GCM，并为每条记录使用唯一随机 nonce。
- 精确查重字段使用 HMAC-SHA256 摘要，不使用无密钥的普通 SHA-256；HMAC 密钥与数据库分离保存。
- 当前 Python 服务接收已经完成加密和 HMAC 的 `bytes`/64位十六进制摘要，密钥处理应位于独立安全组件，不在仓库硬编码。
- 查询视图和普通报表不返回密文、摘要、确认人姓名等敏感字段。
- 密钥需要编号、轮换和吊销机制；记录只保存 `key_version`，密钥由环境密钥服务或受限配置提供。
- 备份文件按敏感数据管理，限制访问并校验 SHA-256；对外演示只使用虚构数据。

## 7. 连接、配置和审计

- `.env` 已被 Git 忽略，`DatabaseConfig` 拒绝空密码和错误数据库名。
- 应用统一使用非 root 账号、`utf8mb4` 和 `+08:00` 会话时区；跨主机连接必须启用 TLS 并校验证书。
- 事务由调用方统一提交或回滚，异常路径不得吞掉错误后继续提交。
- 审计日志至少记录操作者、角色、操作类型、对象编号、结果、时间和关联请求编号，不记录密码、完整密文或会话令牌。
- 定期复核实际授权、异常登录、导出行为、备份访问和高风险结算调整。

## 8. 验收清单

- `06_security_roles_verify.sql` 的 `R01～R07` 全部为 `PASS`；
- Python 查询值使用参数化接口，动态 SQL 片段来自固定白名单；
- Git 中不存在真实密码、密钥、令牌和生产证书私钥；
- 登录安全属于明确设计项，未把尚未实现的统一认证描述为已上线功能；
- 增量备份条件通过 `06_backup_incremental_preflight.sql` 单独检查。
