# 跨模块安装与 D 结算数据链复验（2026-11-21）

## 1. 结论

1. `sql/A/07_verify.sql` 执行后 A 的表、视图、过程、触发器全为 0，**不是 A 的 SQL 缺陷**。该文件是只读验收脚本，本身不创建任何对象；出现 0 说明 A 的 01～04 尚未执行，或执行时缺少 D/B 前置表而失败。
2. 在 **MySQL 8.0.46** 空库上按 `sql/00_install_all.sql` 安装，D/B/A/D 结算对象全部创建成功：43 张表、17 个视图、15 个存储过程、23 个触发器。
3. 仅补装 A（D/B 已有、A 为 0）的场景也已验证：`sql/A/00_preflight.sql` 能定位缺项，`sql/A/00_install_a.sql` 只安装 A 的 01～04，不重复建 D/B。
4. A 结构可用后，B 的固定交易数据生成器 `python -m app.seed_b_integration --commit` 在 8.0.46 成功提交：40 笔已出账且足额支付订单、100 条支付、20 条次月退款。
5. D 的 `sql/D/05_settlement_seed_preflight.sql` 在该数据上得到：
   - `DP03 eligible_settlement_order_count = 40`，PASS；
   - `DP06 available_refund_count = 20`，PASS。
   D 的结算测试数据阻塞已解除。

## 5. 注意事项

1. `sql/D/04_membership_final_verify.sql` 按“仅 D 核心种子”校准了 `user`/`vehicle`/`promotion` 行数。执行 B 固定测试集后行数会超过 20，该脚本会按设计报 FAIL；全模块联调请使用 `sql/00_verify_all.sql`。
2. A 的 `00_local_shared_fixtures.sql` 是本地联调夹具（9101/9301/9401/9501 段），B 固定测试集使用 7200000 段，二者可并存；正式提交材料时应说明替换关系。
3. `sql/00_install_all.sql` 只用于空库；已有 D/B 的库不要重复执行，只跑 `sql/A/00_install_a.sql` 补装 A。
