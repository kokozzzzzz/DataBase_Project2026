## 本次实际改了什么

1. **C正式代码只有一份**：`app/database/c_repository.py`、`app/services/c_service.py`、`app/run_c_demo.py`。原公共通用名和 `yX/c_app` 转为兼容入口，`yX/sql/C` 转发到 `sql/C`。修正公共C服务的错误导入。`pytest.ini` 默认只收集根 `tests`，旧 `yX/tests` 保留为历史副本。
2. **事务统一归调用方**：C的12个存储过程不再自行提交或回滚。用公共 `transaction(connection)` 将设备/告警/工单/库存写入组合成一笔事务。旧手工CALL也必须显式开启并提交事务；报错后必须回滚整笔，不能捕获后继续提交。
3. **设备状态闭环**：C写运行故障/离线/维修结果，B维护资产与生命周期。健康通信可恢复已投运的离线桩，并关闭对应离线待办；健康报文不清除FAULT，故障必须维修复核；旧采集时间的报文留档而不回退状态。故障及维修不覆盖B的人工DISABLED状态。当前恢复以新报文到达为触发，尚未提供独立定时离线扫描器。
4. **修复真实退料/安装错误**：MySQL单表UPDATE按顺序赋值，原过程先增加数量、后计算状态会把本次数量再加一遍，触发CHECK失败。现在先按旧值算状态，再增加数量；领2/装1/退1/复核关单和争抢最后一件均验证。
5. **确定共享停运登记**：C通过 `register_outage_plan` / `finish_outage_plan` 写B已有 `equipment_outage_plan`；A读取同一记录制作公告/定向通知；B与A都读取它判断可用性。没有新增重复实体或设备编号。提前结束用CANCELLED；COMPLETED要求计划结束时间已到。创建计划和发布通知仍是明确的两步，不会自动发通知。
6. **对齐预约宽限**：B允许已核验预约在 `[starts_at, ends_at + late_grace_minutes)` 内开单，右边界拒绝。A仍负责是否核验通过和资格消费。B表结构不变。
7. **安装与验收**：空库总安装包含C；已有库提供补装C/只更新C过程两条路径。C过程计数使用精确前缀，避免SQL LIKE中的下划线误匹配A过程。修正C验收脚本路径及元数据字段名。
8. **本机环境**：组长专用MySQL8.0.46放在 `D:/ChargingPlatform_MySQL_8.0.46`，端口13306。公共连接增加可选 `DB_SSL_CA`；其他成员保留自己的端口、账户和密码。

## 队友拉取后怎么更新

先完成正常Git流程：提交/妥善保存自己未完成的改动，更新dev，再合并dev到个人分支。**拉代码不会自动更新本机数据库。** 在仓库根目录、正确Python环境和本机.env配置下执行以下对应路径。`mysql`不在PATH时在命令后加 `--mysql "完整mysql.exe路径"`。

**从未安装项目、charging_platform为空库**：

```powershell
python -m app.run_sql --file sql/00_install_all.sql
python -m app.run_sql --file sql/00_seed_all.sql
python -m app.seed_b_integration --commit
python -m app.run_sql --file sql/C/05_seed.sql --commit
```

**已有A/B/D表，C的8张表一张都没有**：

```powershell
python -m app.run_sql --file sql/C/00_install_c.sql
# C表为空且B已有桩枪数据时，才执行下面种子；--commit明确提交种子事务：
python -m app.run_sql --file sql/C/05_seed.sql --commit
```

**已经安装C表和旧C过程**：暂停C写入，先备份；只执行：

```powershell
python -m app.run_sql --file sql/C/09_upgrade_routines.sql
```

这条路径只替换12个C过程，保留表、数据、触发器、视图和库存流水。DDL隐式提交，中途失败须按错误位置核对并重跑升级脚本，不是事务整体回滚。C表只建了一部分时先检查对象清单，不套用空库安装，也不要删除现有数据。

`app.run_sql`展开SOURCE后交给MySQL批处理，首个错误即停。MySQL8.0客户端不支持 `--abort-source-on-error`；不要照抄该参数。手工交互SOURCE可能继续执行后面的SOURCE，因此推荐这里的入口。只读验收可以手工SOURCE。

**更新后的验收**：

```powershell
python -m pytest -q
python -m app.run_sql --file sql/00_verify_all.sql
python tests/verify_c_module.py --output C_本机验收
python tests/verify_b_workflow.py --output B_本机流程.json
python tests/verify_abcd_integration.py --output ABCD_本机联调.json
```

最后两条需先生成B固定测试集。普通流程回滚；并发库存用例会新增虚构备件/仓库/工单及不可变流水，成功后退料、复核闭环，保留RACE-前缀审计。请在课设测试库执行；失败后根据前缀通过正式退库/维修流程闭环，不直接删流水。C约束写入测试 `sql/C/08_constraint_tests.sql` 也只用于测试库。
