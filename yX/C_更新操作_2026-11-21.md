## 4. 后续怎么写业务

所有写操作都放进公共事务。原存储过程内的COMMIT已移除，单独调用后忘记提交会在连接关闭时丢失。示例只用于虚构测试设备，将pile_id/gun_id替换成同一桩枪的实际编号：

```python
from app.database.connection import database_connection, transaction
from app.services.c_service import ingest_sample

with database_connection() as connection:
    with transaction(connection):
        with connection.cursor() as cursor:
            cursor.execute('SELECT CURRENT_TIMESTAMP(6) AS t')
            now = cursor.fetchone()['t']
        result = ingest_sample(connection, pile_id=7200002, gun_id=7200002,
            collect_time=now, offline_duration_sec=0, offline_threshold_sec=60)
```

过程报错后应让异常退出事务并整笔回滚，不要吞掉异常后继续提交。流程顺序：采集产生alarm_id→dispatch派单→ACCEPT→ARRIVE→计划/领料→record_part_installation记录实装或return退料→REPAIR→verify复核。关单必须“领用=安装+退回”；库存流水不修改删除，错误用冲正或退料留记录。

正常通信只能恢复符合条件的离线桩，不能清除FAULT或人工DISABLED。离线扫描仍需主动送入相应报文，本次没有后台定时采集器。停运登记调用公共 `register_outage_plan`，将返回编号交A做定向通知，B自动读取同一共享表拦截开单；不再等确认谁登记。
